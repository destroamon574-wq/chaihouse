# 🚀 Как выложить ЧайHouse на GitHub — пошаговая инструкция

Проект полностью готов к публикации: README, лицензия MIT, .gitignore, история коммитов.
Осталось только создать репозиторий на GitHub и отправить код. Ниже — все шаги.

---

## Шаг 1. Создайте репозиторий на GitHub (2 минуты)

1. Откройте <https://github.com/new> (вы уже залогинены как **destroamon574-wq**)
2. Заполните форму:
   - **Repository name**: `chaihouse`
   - **Description** (скопируйте):
     ```
     Сайт чайханы: онлайн-бронирование столов и залов, админ-панель, кабинет владельца. Flask + SQLite + Tailwind CSS. 112 автотестов, CSP с nonce, тёмная тема.
     ```
   - **Public** (для портфолио нужно именно это)
   - ❗ **НЕ** ставьте галочки «Add a README», «Add .gitignore», «Add a license» — всё это уже есть в проекте
3. Нажмите зелёную кнопку **Create repository**

## Шаг 2. Отправьте код (1 минута, в терминале проекта)

Откройте PowerShell в папке проекта и выполните по одной команде:

```powershell
cd "C:\Users\Jony\Documents\Сайты для портфолио\ЧайHouse"

# 1) Связать локальный проект с репозиторием
git remote add origin https://github.com/destroamon574-wq/chaihouse.git

# 2) Переименовать основную ветку в main (GitHub так ожидает)
git branch -M main

# 3) Отправить код
git push -u origin main
```

**При первом push появится окно авторизации** (Git Credential Manager):
- откроется браузер с запросом «Git Credential Manager · authorize»
- нажмите зелёную кнопку **Authorize**
- если браузер попросит пароль GitHub — введите (это безопасность, не капча)

После этого код уйдёт в репозиторий. Вкладка авторизации больше не понадобится —
Windows запомнит доступ.

> 💡 Если окно авторизации не появилось, а в терминале ошибка `403` или `Authentication failed` —
> выполните `git credential-manager github logout` и повторите `git push`.

## Шаг 3. Наведите красоту на странице репозитория (2 минуты)

1. **Описание и topics**: на странице репозитория справа нажмите ⚙ (About):
   - Description — уже задан при создании (если нет, вставьте из Шага 1)
   - **Topics** (каждое через Enter): `flask` `python` `sqlite` `tailwindcss` `alpinejs` `htmx` `jinja2` `booking-system` `restaurant-website` `dark-theme` `csp` `pytest`
   - ✅ **Releases** и ✅ **Packages** можно оставить как есть
2. **Закрепите репозиторий в профиле**: откройте свой профиль → `Customize your pins` → выберите `chaihouse`

## Шаг 4. Проверьте README на странице репозитория

GitHub покажет `README.md` с описанием проекта — там уже есть стек, быстрый старт,
инструкция по запуску в PyCharm, Telegram-уведомления и архитектура.

Хотите добавить скриншоты в README? Сделайте 2–3 скриншота сайта (главная, меню,
бронирование), положите их в папку `docs/screenshots/` и вставьте в README:

```markdown
![Главная](docs/screenshots/home.png)
![Меню](docs/screenshots/menu.png)
```

И закоммитьте:

```powershell
git add docs/screenshots
git commit -m "Добавить скриншоты"
git push
```

## Шаг 5 (опционально). Живая ссылка для портфолио

GitHub хранит код, но Flask-сайт на GitHub Pages работать не будет (нужен Python-сервер).
Бесплатно поднять живую демо-версию можно на:

| Сервис | Бесплатный план | Что сделать |
|---|---|---|
| **Render** (рекомендую) | ✔ | Create → Web Service → подключить GitHub-репо → Build: `pip install -r requirements.txt` → Start: `python app.py` |
| **Railway** | пробный | New Project → Deploy from GitHub |
| **PythonAnywhere** | ✔ | Загрузить код, создать веб-приложение Flask вручную |

На Render задайте переменную окружения `SECRET_KEY` (любая случайная строка) — она есть в `.env.example`.

Ссылку на живую версию добавьте в начало README и в описание репозитория — рекрутер сможет
кликнуть и увидеть сайт сразу.

## Мини-словарь, если что-то пойдёт не так

| Ошибка | Решение |
|---|---|
| `remote origin already exists` | `git remote set-url origin https://github.com/destroamon574-wq/chaihouse.git` |
| `failed to push some refs` | Обновите страницу репозитория и повторите `git push -u origin main` |
| `_authentication failed_` | `git credential-manager github logout` → снова `git push` |
| Репозиторий пустой после push | Обновите страницу (F5) — GitHub иногда не сразу показывает |

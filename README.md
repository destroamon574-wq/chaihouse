# ЧайHouse — сайт чайханы

Локальный демонстрационный сайт чайханы «ЧайHouse» на Ходынском бульваре: публичные страницы, демо-меню, залы, галерея, онлайн-бронирование столов и залов, личный кабинет гостя, админ-панель и кабинет владельца.

Проект полностью работает офлайн: изображения — локальные SVG, карта — локальная схема, внешние CDN не используются. Деплой и публикация не выполнялись.

## Стек

- Python 3.11+ (проверено на Python 3.15)
- Flask 3.1
- SQLite (`sqlite3`, без ORM) + собственные миграции
- Jinja2, ванильный JavaScript, собственный CSS
- pytest + Flask test client
- Pillow — только для генерации OG-обложки (в рантайме не требуется)

### Фронтенд

- **Tailwind CSS v3.4** — скомпилированный CSS (standalone CLI, без Play CDN): `tailwind.config.js` в корне, тёмная тема `darkMode: 'class'`, палитра бренда (charcoal / sand / brass / terra)
- **Alpine.js, HTMX, Lucide, Toastify** — захостованы локально в `static/vendor/` (сайт работает без интернета)
- **Единая дизайн-система** — `docs/DESIGN.md`: типографика (Georgia + Inter), pill-кнопки, микро-взаимодействия, тёмная тема для всего сайта
- **CSP без `unsafe-inline`** — inline-скрипты только с per-request nonce, стили только из внешних файлов

## Быстрый старт (терминал)

```powershell
cd "C:\Users\Jony\Documents\Сайты для портфолио\ЧайHouse"

# 1. Виртуальное окружение (рекомендуется)
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 2. Зависимости
python -m pip install -r requirements.txt

# 3. Настройки окружения
Copy-Item .env.example .env
# откройте .env и задайте SECRET_KEY, при необходимости SITE_URL

# 4. Запуск
python app.py
```

Сайт откроется на <http://127.0.0.1:5000>.

Альтернативный запуск через Flask CLI:

```powershell
flask --app app run --debug --port 5000
```

При первом запуске автоматически создаются:

- `instance/chaihouse.db` — база данных;
- `instance/uploads/` — каталог загружаемых изображений;
- схема и демо-данные: 4 зала, 18 столов, 7 категорий меню, 20 блюд, отзывы, брони, настройки.

Повторный запуск не перезаписывает данные: сид идемпотентный.

## Запуск в PyCharm

### 1. Откройте проект

`File → Open…` → выберите папку `ЧайHouse` (ту, где лежит `app.py`).

### 2. Настройте интерпретатор

1. `File → Settings → Project: ЧайHouse → Python Interpreter`.
2. Нажмите `Add Interpreter → Add Local Interpreter…`.
3. Выберите `Virtualenv Environment → New` (или `Existing`, если `.venv` уже создан).
4. Base interpreter — Python 3.11 или новее. ОК.
5. В терминале PyCharm (`Alt+F12`) выполните:

   ```powershell
   python -m pip install -r requirements.txt
   ```

### 3. Создайте файл `.env`

В корне проекта создайте `.env` (можно скопировать `.env.example.off`) и задайте:

```dotenv
SECRET_KEY=любая-длинная-случайная-строка
FLASK_ENV=development
DEMO_MODE=1
SITE_URL=http://127.0.0.1:5000
```

Файл `.env` читается при старте приложения. В репозиторий он не добавляется.

### 4. Создайте Run Configuration

**PyCharm Professional (удобнее):**

1. `Run → Edit Configurations… → + → Flask Server`.
2. Поля:
   - **Target type**: `Module name`
   - **Target**: `app`
   - **Application factory**: `create_app` (включите чекбокс)
   - **Additional options**: `--port 5000` (при необходимости)
   - **Working directory**: корень проекта
   - **Python interpreter**: созданный `.venv`
3. ОК → выберите конфигурацию в списке → `Run` (Shift+F10).

**PyCharm Community:**

1. `Run → Edit Configurations… → + → Python`.
2. Поля:
   - **Script path**: `...\ЧайHouse\app.py`
   - **Parameters**: оставьте пустым
   - **Working directory**: корень проекта
   - **Python interpreter**: созданный `.venv`
3. ОК → `Run`.

В конце `app.py` уже есть точка входа:

```python
if __name__ == "__main__":
    create_app().run(debug=True)
```

Поэтому скрипт запускается напрямую, без дополнительных параметров.

### 5. Откройте сайт

Перейдите по ссылке из консоли: <http://127.0.0.1:5000>.

### 6. Запуск тестов в PyCharm

1. `File → Settings → Tools → Python Integrated Tools`.
2. **Default test runner** → `pytest`.
3. В дереве проекта щёлкните правой кнопкой по папке `tests` → `Run 'pytest in tests'`.

Или в терминале:

```powershell
python -m pytest -q
```

### Частые вопросы по PyCharm

- **Порт 5000 занят.** Запустите на другом порту: в конфигурации добавьте `--port 5001` или в терминале `python -c "from app import create_app; create_app().run(port=5001)"`.
- **Не видно Flask Server в списке конфигураций.** Это функция PyCharm Professional. В Community используйте конфигурацию `Python` с `app.py`.
- **Изменения в шаблонах не применяются.** Перезапустите сервер: `TEMPLATES_AUTO_RELOAD` не включён. В debug-режиме перезагрузка шаблонов обычно работает, но после правок CSS/JS обновите страницу с `Ctrl+F5`.
- **Нужно сбросить демо-данные.** Остановите сервер, удалите `instance/chaihouse.db`, запустите снова — база создастся и заполнится заново.
- **Ошибка `ModuleNotFoundError: flask`.** Интерпретатор PyCharm указывает не на то окружение либо зависимости не установлены. Проверьте interpreter и выполните `pip install -r requirements.txt`.

## Что умеет сайт

### Публичная часть (доступна без регистрации)

- `/` — главная: hero, фирменные блюда, залы, отзывы, JSON-LD `Restaurant`.
- `/menu` — меню с поиском, фильтрами по категориям, тегам и сортировкой.
- `/menu/<slug>` — карточка блюда, состав, аллергены, калорийность.
- `/halls`, `/halls/<slug>` — залы, вместимость, оснащение.
- `/gallery` — галерея с фильтрами и лайтбоксом.
- `/about`, `/contacts`, `/reviews` — о чайхане, контакты, отзывы гостей.
- `/privacy`, `/terms` — документы.
- `/robots.txt`, `/sitemap.xml`, `/healthz`.

Регистрация не требуется для просмотра сайта, меню, залов, галереи, отзывов и контактов.

### Бронирование (только после входа)

- `/booking` — выбор зала, даты, времени и стола; проверка пересечений по времени.
- Слоты 12:00–22:00, длительность 2 часа, горизонт бронирования — 90 дней.
- Статусы: `pending`, `confirmed`, `cancelled`, `declined`, `completed`.
- `/booking/success/<code>` — подтверждение, `.ics`-файл для календаря, отмена.
- `/booking/lookup` — поиск брони по коду и телефону.
- Гость может отменить свою бронь; администратор — подтвердить, отклонить или завершить.

### Личный кабинет гостя

`/account/` — ближайшие брони, уведомления, избранное, история.
`/account/settings`, `/account/password`, `/account/export`, `/account/delete` — профиль, смена пароля, экспорт данных, удаление аккаунта с анонимизацией броней.

### Админ-панель (`/admin/`, роли admin и owner)

- брони: поиск, фильтры, карточка, смена статуса, причина;
- календарь недели (`/admin/calendar`): загрузка залов по дням, счётчики гостей, переходы между неделями;
- меню: создание, редактирование, скрытие, удаление блюд, загрузка изображения или выбор готового пресета;
- залы и столы: редактирование зала, добавление и скрытие столов;
- галерея: загрузка PNG/JPEG/WebP с проверкой сигнатуры, удаление;
- отзывы: публикация, отклонение, ответ администратора, сохранение черновика ответа;
- журнал действий `audit_log`.

### Кабинет владельца (`/owner/`, только owner)

- аналитика: выручка, брони, загрузка залов, графики, повторные гости, конверсия в визит, средний размер компании по дням недели, заполненность залов за месяц;
- управление ролями пользователей;
- настройки сайта (название, адрес, телефон, часы, координаты, лимиты, Telegram для уведомлений о бронях);
- экспорт броней в CSV;
- экспорт пользовательских данных;
- резервная копия базы в один клик.

## Telegram-уведомления и письма гостям

1. **Telegram (мгновенные сообщения о новых бронях)**: создайте бота у @BotFather, добавьте его в чат/группу ресторана, узнайте ID чата у @userinfobot. Заполните поля в «Кабинет владельца → Настройки» или пропишите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `.env`.
2. **Письма гостям (подтверждение/отмена брони и напоминание за день)**: задайте в `.env` переменные `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`. Без SMTP письма мягко пропускаются — сайт работает как раньше.
3. **Ежедневные напоминания**: один раз в день (лучше утром) запускайте
   `flask --app app send-reminders` — гостям с завтрашними подтверждёнными бронями уйдут письма, а брони получат пометку `reminded_at` (повторно не отправляются).

## Резервные копии базы

- Кнопка «Сделать бэкап БД» в кабинете владельца.
- Команда `flask --app app backup-db` или скрипт `python scripts/backup_db.py`.
- Копии лежат в `instance/backups/`, хранятся последние 14.
- Для автоматизации повесьте скрипт на планировщик Windows (`schtasks`) или cron (ежедневно).

## Замена демо-меню и фотографий

Сейчас в проекте демонстрационные блюда и SVG-иллюстрации. Чтобы поставить реальные данные:

1. Войдите как `admin@chaihouse.ru` или `owner@chaihouse.ru`.
2. Откройте `/admin/menu`.
3. Создайте блюдо или откройте существующее.
4. Заполните название, цену, вес, состав, аллергены, калорийность.
5. В блоке изображения:
   - выберите готовый SVG-пресет, либо
   - загрузите PNG/JPEG/WebP (до 3 МБ). Файл проверяется по расширению и сигнатуре, сохраняется под случайным именем в `instance/uploads/`, публикуется через `/media/<filename>`.
6. При необходимости снимите галочку «Активно», чтобы скрыть блюдо с сайта без удаления.
7. Аналогично обновите залы в `/admin/halls` и галерею в `/admin/gallery`.

Категории меню заданы в `database.py` (демо-сид). Для изменения набора категорий отредактируйте сид или добавьте записи в таблицу `menu_categories`.

## Безопасность

- Пароли — `scrypt` через Werkzeug; смена пароля инвалидирует старые сессии (`session_version`).
- CSRF-токены для всех POST/PUT/PATCH/DELETE.
- Rate limiting на вход, регистрацию, сброс пароля, отзывы и поиск брони.
- Строгая CSP без `unsafe-inline`, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`.
- Cookie: `HttpOnly`, `SameSite=Lax`, `Secure` в production.
- Экранирование Jinja2; JSON-LD вынесен в шаблон без inline-скриптов.
- Загрузки: белый список расширений, проверка сигнатур PNG/JPEG/WebP, случайные имена, лимит 4 МБ на запрос.
- Приватные страницы отдают `noindex, nofollow` и закрыты в `robots.txt`.
- SQL — только параметризованные запросы; для кириллического поиска зарегистрирована SQLite-функция `py_lower`.

## Доступность и SEO

- Семантическая разметка, skip-link, корректный порядок заголовков, `aria-label` и `role="img"` у звёзд рейтинга.
- Контраст текста проверен Lighthouse.
- Lighthouse (главная, меню, залы, галерея, отзывы, вход): Accessibility / Best Practices / SEO — 100.
- Canonical, Open Graph, JSON-LD `Restaurant`, `sitemap.xml`, `robots.txt`.

Значения Lighthouse измерены в локальном браузере без мобильной эмуляции; для мобильной проверки используйте DevTools → Device Toolbar.

## Ограничения демо

- Реальная оплата, SMS и email-рассылка не подключены: уведомления и сброс пароля работают внутри сайта (ссылка сброса показывается на странице в демо-режиме).
- Данные и изображения демонстрационные.
- Проект не опубликован в интернете и не предназначен для production без настройки HTTPS, WSGI-сервера, резервного копирования и реальной почты.
